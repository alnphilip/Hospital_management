Smart Hospital

Workflow Management System

A comprehensive, full-stack platform digitizing hospital operations. From patient registration to digital prescriptions, managed through deeply customized, role-based dashboards.

The Core Concept

Replacing fragmented paper trails and disconnected software with a unified, strictly-governed digital pipeline.

Unified Ecosystem

Patients, Doctors, Staff, and Admins operate on one platform. Each role sees a customized dashboard, displaying only the data required to perform their specific duties.

Managed Pipelines

Appointments follow a strict state machine: Pending → Verified → Assigned → Completed, with clear responsibility handoffs at each stage.

Zero-Trust Security

Data isolation is enforced at the database level via Row Level Security (RLS). A user physically cannot query data that does not belong to them.

Defence In Depth

Access control implemented at every layer of the application.

Row Level Security (RLS)

Every SQL query is intercepted by database policies. For example, when a patient fetches /api/patient/appointments, Postgres implicitly applies WHERE patient_id = auth.uid(). The Node server cannot accidentally return another patient's data.

Anti-Escalation

Public signups (/register) have role: 'patient' hardcoded. No one can register as a Doctor or Staff. Those accounts can only be provisioned via an Admin-only API utilizing a secure server-side SERVICE_ROLE_KEY.

Next.js Edge Middleware

Before any React component renders, Edge Middleware inspects the browser JWT. If a Doctor types /dashboard/admin into the URL bar, the request never hits the server—it instantly redirects to /dashboard/doctor.

The Appointment Pipeline

A linear progression designed to eliminate dropped communications.

1. Pending

Patient Creation

Patient selects an available department, date, time, and enters their symptoms. The appointment enters the system awaiting review.

2. Verified

Staff Triage

Staff views the global queue. They verify the department exists, time is reasonable, and mark it verified.

3. Assigned

Doctor Allocation

Staff queries available Doctors within the requested department and maps the Appointment to a specific Doctor ID.

4. Completed

Consultation & Prescription

Doctor marks the appointment complete from their dashboard and generates an immutable JSONB digital prescription for the patient.
